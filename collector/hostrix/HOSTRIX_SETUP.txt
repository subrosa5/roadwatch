Hostrix recovery after pip ENOSPC

1. Stop the server; disable automatic restart during preflight.
2. Upload and extract this archive, replacing project files only.
3. Startup: Python 3.12; uncheck "Install packages first (requirements.txt)".
4. Set Startup command to: python3 -u hostrix_bootstrap.py --repair
   Save command. If using Files to run instead, select ONLY hostrix_bootstrap.py.
5. Keep ROADWATCH_MODE=preflight. No private API secrets needed for this check.
6. Start once. The bootstrap reports disk information, purges only the current
   runtime account's pip cache, then installs exact binary wheels one at a time
   into .rw-packages. Downloads use .rw-install-tmp instead of system /tmp.
7. Look for dependencies_ready, isolated_imports_verified, and the model preflight
   report. If Hostrix STILL prints "Installing requirements" before our stage
   disk_diagnostics, its automatic installer is still active. Stop and recheck
   the Startup checkbox and command; repeated attempts will not fix disk limits.
8. Send the log if ENOSPC persists: project quota, /tmp, inode limits or the
   provider's underlying filesystem may be full. No paid upgrade is needed to
   diagnose that distinction. Do not delete system directories or model data.
9. After successful preflight, actual monitoring still needs the two private
   runtime secrets and ROADWATCH_MODE=run. Original privacy rules still apply.

This installer does not uninstall or modify global Python packages. Only the
pinned headless OpenCV copy in this project is used by the app. The full target
package set and actual disk footprint must be verified on this provider.

Updating an already running instance: Upload this ZIP and Unzip with replacement.
Version 4: continuous HLS passthrough with media-time annotations (no re-encoding),
45-second recorder watchdog, and no repeated upload of expired frame packets.
The website and collector must both support v4 for synchronized video boxes.
Do NOT use Redeploy: keep .rw-packages, data and existing environment secrets.
Keep ROADWATCH_MODE=run and the same bootstrap command. This build requests up to 4 fps; preflight selects 2-4 fps from measured load,
36000 inference CPU seconds/day, and bounded tracking frame batches. All objects
share a forward/backward optical-flow calculation. Real-stream admission may retry
a lower cadence at most twice; memory and freshness limits remain enforced. Dependencies
and model hashes are unchanged. Fresh/stale status is not accuracy validation.
