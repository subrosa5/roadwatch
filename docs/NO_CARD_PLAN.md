# План с жёстким запретом банковской карты

Актуально на **13 ноября 2026 года**. Пользователь исключил любую привязку карты, включая верификацию и нулевое списание. Бюджет — 0 ₽, production не использует его компьютер. При противоречивых или неподтверждённых требованиях платёжного метода сервис не включается в обязательный стек.

Этот план имеет приоритет над предварительным выбором провайдеров в RESEARCH_OPTIONS.md. Цель 50–100 камер остаётся; ниже описан последовательный способ проверить её достижимость, а не замена цели на несколько камер.

## Что исключено из обязательного плана

| Кандидат | Основание |
|---|---|
| Oracle Free Tier | [FAQ](https://www.oracle.com/cloud/free/faq/) прямо описывает обязательную проверку карты при регистрации |
| Modal | [Billing docs](https://modal.com/docs/guide/billing) требуют payment method on file для использования; бесплатные кредиты это требование не отменяют |
| Northflank | [Billing docs](https://northflank.com/docs/v1/application/billing/pricing-on-northflank) требуют payment method для всех пользователей; pricing говорит обратное. При текущем ограничении не предлагать регистрацию как обязательный шаг |
| Обычные GCP/Azure/AWS compute и неизвестные trial | Не считать доступными без карты до подтверждения конкретного способа регистрации и получения ресурса. Это исключение из плана, не утверждение, что любая программа всегда требует карту |
| R2 и иные billing-подписки | У [R2](https://developers.cloudflare.com/r2/get-started/) отдельный checkout/subscription; не переносить обещание no-card Workers на другие продукты |
| Гранты с неизвестными платёжными условиями | Не считать выданными ресурсами. Допустить только после явного подтверждения запуска без карты, предоплаты, платного перерасхода и обязательств пользователя |

## Выбранная основа

**Frontend:** уже опубликованный приватный интерфейс. Его наличие не подтверждает работу collector.

**Небольшой API и журнал:** кандидат Cloudflare Workers Free + D1 Free. [Workers](https://www.cloudflare.com/products/workers/) прямо предлагает старт без карты. Сначала проверяется доступность аккаунта и именно бесплатных продуктов; при появлении требования payment method остановить настройку. Стандартный Worker не является постоянной VM с FFmpeg. API проекта сейчас использует Node SQLite: перенос потребует адаптера, миграций и проверки квот, автоматически он не выполнен.

**Видеофрагменты:** прежде всего read-only архив оператора по разрешённому API. Если архив отсутствует, статус события должен явно показывать «видео недоступно». Набор отдельных JPEG не называть записью ДТП. Дополнительное storage не подключать автоматически.

**CV и приём:** вычислительный ресурс пока не выбран. Нет подтверждённого постоянного no-card runtime, достаточного для полного видеопайплайна. Serverless/AI free allowance можно исследовать на одном источнике, но он не доказывает пригодную incident-модель, допустимую частоту или наличие pre-roll. Не обещать работу 24/7 до реального теста.

## Последовательность действий

1. **Источник до регистрации в облаке.** Найти один разрешённый свежий источник Москвы/области. Проверить JPEG API, разрешённую частоту и архив t−20…t+10. Направление камеры, время и условия использования фиксируются отдельно. Сейчас источников 0.
2. **Основа приложения без карты.** Подготовить Workers/D1 вариант API для журнала, статусов, просмотра событий и авторизации. Deploy возможен после предоставления доступа к no-card аккаунту. Хранить события независимо от открытой вкладки; не выдавать это за работающий CV.
3. **Один полный эксперимент.** На разрешённых данных проверить модель дыма/огня, временное подтверждение и получение клипа. Сначала допускается ограниченный облачный эксперимент. Если он работает только с сессиями/перерывами, так и обозначать.
4. **Постоянный обработчик.** Получить предоставленный партнёром сервер либо грантовый runtime с документированными no-card условиями. Альтернатива — разрешённый API событий владельца камер. Для внешней инфраструктуры также нужны CPU, decode, сеть и storage; грант оплачивает их вместо пользователя.
5. **Пилот 24/7.** Один источник 24 часа, затем 5/10 по 72 часа; измерить пропуски, ложные тревоги, задержку, нагрузку и полноту записи. Для ДТП дополнительно нужны временные данные и отдельная проверка качества.
6. **Масштабирование к 50–100.** Только при достаточном числе разрешённых источников и измеренном запасе облачных ресурсов. Снимки каждые несколько секунд могут помочь с устойчивым дымом/последствиями, но не гарантируют обнаружение момента столкновения.

## Критерий честного запуска

Сайт, журнал и ограниченные эксперименты можно развивать отдельно. Статус «реальный мониторинг 24/7» появляется только при работающих источнике, постоянном compute, модели и записи/архиве. Если no-card compute и источник не предоставлены, этот статус остаётся «не запущено».

Render Free допускает аккаунты без платёжного метода, но [засыпает и теряет локальные файлы](https://render.com/docs/free); не назначать его постоянным recorder. Colab/Kaggle/ZeroGPU оставляем для допустимых ограниченных экспериментов, а GitHub Actions — для CI. Бесконечные перезапуски jobs и искусственный keep-alive не являются планом production.

Следующий технический шаг — проверенный источник и подготовка независимого no-card API. Следующий внешний ресурс для полного запуска — сервер/грант/событийный API партнёра **без карты**. Заявки, регистрации и сообщения третьим лицам не отправлены.
