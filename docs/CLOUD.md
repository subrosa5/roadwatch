## Данные и режимы

- Обычная консоль читает реальный журнал. Сейчас он пуст.
- `?cloud-demo=1` читает отдельные синтетические события из D1, их JPEG и MP4 из BUCKET. Состояние review сохраняется на сервере.
- `?demo=1` — прежняя автономная демонстрация браузера, её review остаётся локальным.
- Публичные плееры владельца — просмотр без серверного CV. На них не рисуются искусственные рамки. Счётчик обработанных камер не увеличивается от открытия iframe.

Рамки API выдаются только с matching frame_id. Поля health/receiving относятся к принятым наблюдениям, а не к доступности player HTML. Событие после двух кадров — кандидат для человека. Для хранения клипа требуется настоящий MP4; отсутствие записи отмечается явно.

## Авторизация

Site остаётся owner-private. Платформа Sites проверяет вход посетителя и передаёт oai-authenticated-user-id; UI использует тот же origin без ручного копирования токена. Записи дополнительно требуют same-origin и X-Roadwatch-Write.

Для внешнего collector нужны два независимых секрета: Sites service access и INGEST_TOKEN. Они не помещены в репозиторий или браузер. Service access получен штатным чтением существующего Site, не создавался или не ротировался для обхода. Runtime INGEST_TOKEN сохранён как секрет Sites.

Collector поддерживает SITES_SERVICE_TOKEN только для HTTPS *.chatgpt.site, запрещает URL с credentials/query/fragment и не следует API redirects. Его реальное облачное выполнение пока не запущено. Общие тесты используют только фиктивные токены.

## Worker API

GET: `/api/health`, `/api/cameras`, `/api/events`, `/api/stats`, `/api/capacity`, `/api/sources`, `/api/cameras/:id/frame`, `/api/evidence/:id`.

POST: `/api/observations`, `/api/cameras/:id/frame`, `/api/events/:id/evidence`, `/api/events/:id/review`, `/api/ops/init`, `/api/ops/probe-sources`, `/api/ops/retention`.

`demo=1` на GET cameras/events/stats выбирает учебные данные. Ingest принимает только включённые и одобренные камеры с согласованным demo provenance. Browser owner не имеет collector role. Init синхронизирует предусмотренные кодом настройки, но не включает реальные источники.

Ограничения Worker: 500 наблюдений/сутки, 100 MiB на готовые/резервируемые клипы, 25 MiB на MP4, 2 MiB на JPEG, 1 MiB на JSON. Это защитные настройки проверки, не готовая квота непрерывного анализа трёх камер. Перед увеличением нужно измерение ресурсов Sites и приёма видео.

Retention endpoint удаляет до 100 клипов старше 7 дней, до 500 наблюдений старше суток и до 20 старых snapshots за вызов; hash metadata сохраняется. Автоматическое расписание cleanup пока не настроено. Незапущенный cleanup не позволяет расти бесконечно: admission cap останавливает новые evidence. После аварии во время upload может оставаться reserved metadata; durable upload reconciliation ещё нет.

- Браузер локального UI: desktop/mobile, события, review, калькулятор и API.

## Исходники и сборка

`cloud/worker.mjs` — отдельный Worker API. `cloud/schema.sql` — исходная схема. `src/core.mjs` — общий переносимый валидатор и temporal logic; Node digest остаётся в domain.mjs.

`npm run build:cloud` собирает автономный Worker с встроенными ресурсами в игнорируемый cloud-build. Миграция для Sites подготовлена в Drizzle layout; изменения после её применения делаются только новыми migrations. Для существующего Site source helper открывает его checkout, после чего выполняется `node tools/build-cloud.mjs .` и штатные packaging/publication.

`tools/cloud-verify.mjs` получает credentials скрытым stdin; не передавать их аргументами shell и не сохранять в файлах. Код проверки не содержит реальных секретов. После публикации повторно читать реальные D1/R2, не заменять проверку только локальным mock.

## Что ещё не выполнено

Свежие видеопотоки получены и подключены к просмотру. Не установлен и не оценён trained checkpoint ДТП/дыма/огня. Нет постоянного inference/FFmpeg worker, гарантированного pre-roll, активного расписания CV, durable retries и push при закрытом браузере. Worker с HTTP API и файловым хранилищем не заменяет эти компоненты.

Следующий реальный критерий: проверенный буфер → измеренный inference в доступном no-card runtime → приём первого настоящего наблюдения. До этого `monitoring=false`, реальные события не создаются. Требование выполнить систему целиком остаётся открытым; v0.2 закрывает облачный журнал/клипы, а не весь 24/7 мониторинг.
