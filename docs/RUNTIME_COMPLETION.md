# Завершение облачного контура

14 ноября 2026. Это текущая спецификация; при расхождении с ранними планами она имеет приоритет.

## Что реализовано

- Одна одобренная CV-камера CBTV51, вторая WWDTV039 остаётся для просмотра. Источники не зависят от России.
- Отдельный heartbeat процесса раз в минуту: online требует свежего heartbeat <180 секунд и последнего inference-кадра <20 секунд. Архивный JPEG с периодом 15 минут не выдаётся за активный live-анализ.
- Анализ по запросу: viewer lease 35 секунд, обновление видимого окна каждые пять секунд, единый R2-объект JPEG с метаданными его рамок. Рамки рисуются после загрузки совпадающего кадра и учитывают letterboxing. При скрытии вкладки lease освобождается/истекает. HLS остаётся отдельным режимом.
- Лимит preview 6000/сутки отдельно от архивных наблюдений 500/сутки. Коллектор допускает не более 400 попыток архивной публикации и пяти клипов/сутки; обычно 96 тихих наблюдений/сутки. Ограничения backend остаются авторитетными после потери диска хоста.
- Поток FFmpeg перезапускается с backoff. Сетевые 5xx/временные конфликты повторяются, ошибки авторизации не маскируются. Клип формируется из закрытых сегментов CSV, без перекодирования H.264. До заполнения кольца полный pre-roll не обещается.
- Дисковый outbox клипов до 30 МиБ переживает рестарт. Повтор той же записи не расходует квоту повторно. Незавершённая запись R2/D1 восстанавливается по размеру, SHA-256 и event_id.
- Retention: наблюдения сутки, записи семь суток, журнал/hash остаются. Ограниченная очистка запускается обращениями к авторизованному API не чаще раза в пять минут и ежечасным запросом коллектора. Независимого таймера при полном отсутствии коллектора и API-трафика нет.
- Opt-in Web Push: P-256/VAPID, RFC8291 AES128GCM, до пяти подписок, только известные HTTPS push endpoints, только реальные события. Очередь ждёт клип 25 секунд, повторяет временные отказы, удаляет 404/410. Service worker не кеширует приватные страницы. Delivery at-least-once; tag подавляет повтор видимого уведомления.
- VAPID-ключ выводится из существующего серверного INGEST_TOKEN с отдельным доменом применения; новый runtime-секрет не нужен. Ротация ingest меняет push-ключ и требует новой подписки. Endpoint подписчика не публикуется в реестре источников.

## Выполненные проверки

- 36 Node-тестов: авторизация/роли, квоты, события, R2/Range, восстановление uploads, heartbeat, lease/preview, push. Ciphertext независимо расшифрован библиотекой http_ece, ES256 подпись проверена Node crypto. Это не доказательство доставки на конкретный телефон.
- Python: 6 тестов публикации, 4 механики коллектора, 3 retries/outbox. Browser QA проверяет режимы live/analysis, совпадение рамок, отсутствие автоматического запроса разрешений.
- Полный транспортный E2E: FFmpeg → Python collector → Worker/D1/R2 → событие → MP4 → HTTP Range; preview и heartbeat читаются обратно. Используется явно синтетическая сцена и тестовый detector; production API и реальные инциденты не затрагиваются. Сохранённый клип 159204 байта; SHA-256 b91957c99bb0d4e823d8a2a767dae5bfc6e1860f688aef2190c6c7bff6013a71.
- Предыдущий облачный Linux probe реального огонь/дым inference: [GitHub Actions](https://github.com/subrosa5/roadwatch/actions/runs/43472594823), ограничение 0.5 CPU / 512 МиБ, медиана CPU 46.32 мс/кадр, консервативная сумма high-water RSS 228.29 МиБ. Это короткая проверка, не работа Botkeep 24/7.

## Исследование ДТП

Добавлены `collector/collision.py`, lockfile и `tools/eval_collision.py` для отдельной offline-оценки модели [akhra92/dashcam-collision-rockchip-mnv3s](https://huggingface.co/akhra92/dashcam-collision-rockchip-mnv3s), revision 67c3595e1336dcf77cca3cd72c0ad23a540235f7. Два ONNX-файла проверяются по SHA-256. MobileNetV3-small + temporal head: окно 16 кадров, 16 fps, stride 3, три последовательных положительных окна. Выход — классификация сцены без bbox.

Короткий реальный Iowa-фрагмент: 66 кадров, 17 окон, score 0.02–0.064, кандидатов 0, CPU 0.169 секунды, RSS 109 МиБ на машине разработки. Это проверка исполнения, не accuracy benchmark и не результат под лимитом Botkeep. Dashcam-домен отличается от стационарного CCTV. Положительные и отрицательные размеченные Iowa-события не проверены; публикация ДТП в production намеренно отсутствует. Выдуманных рамок или происшествий нет.

## Что не подтверждено

Запуск на аккаунте Botkeep, многосуточная доступность бесплатного хоста, качество огонь/дым на этом ракурсе, реальная доставка push на устройстве владельца. Только после выполнения [последних действий](OWNER_FINAL_STEPS.md) можно измерять фоновую работу. Ни один тест не доказывает обнаружение всех пожаров или ДТП.

## Runtime API

Все маршруты требуют приватного доступа Sites и роли приложения. Service дополнительно передаёт INGEST_TOKEN; браузер использует свою owner identity. JSON-ответы приватные, без общего кеша.

| Маршрут | Роль / назначение |
| --- | --- |
| POST `/api/cameras/:id/heartbeat` | Service; state, counters, last_frame_at, model, capabilities |
| POST / DELETE `/api/cameras/:id/view` | Начать / завершить lease просмотра |
| GET `/api/cameras/:id/demand` | Service; active, until, preview_interval_seconds |
| POST `/api/cameras/:id/preview` | Service; observation + base64 JPEG ≤256 КиБ, совпадающий camera_id |
| GET `/api/cameras/:id/preview` | observation + base64 JPEG атомарно; stale при возрасте >20 секунд |
| GET `/api/push/settings` | Публичный VAPID ключ и число подписок, без endpoints |
| POST / DELETE `/api/push/subscription` | Только browser viewer; endpoint + keys p256dh/auth |
| POST `/api/ops/maintenance` | Принудительный ограниченный проход retention и push-очереди |
| GET `/api/stats` | collectors_online, monitoring, preview_quota, maintenance |

400 означает невалидный payload; 401/403 — исправить роль/секрет или разрешение камеры; 404 preview до первого кадра нормален; 409 evidence — повторить позже при активной резервации; 429/507 — лимит, не обходить ротацией идентификаторов. Коллектор прекращает повторную публикацию при квоте до смены суток UTC. Сетевые повторы ограничены и не следуют redirects с секретами.
