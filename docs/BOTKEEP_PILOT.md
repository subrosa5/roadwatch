# Подготовка первого фонового пилота Botkeep

Обновлено: 14 ноября 2026. Производственный сервер Botkeep ещё не создан: нет авторизованного доступа к аккаунту/панели. В каталоге подключений Botkeep не найден. Утверждать, что постоянный мониторинг уже работает, нельзя.

## Что уже сделано

- Подготовлен Python ZIP без Docker, системного apt/root и секретов. Старт: `python main.py`.
- FFmpeg поставляется через imageio-ffmpeg; модель скачивается с закреплённой версии и проверкой SHA-256.
- Модель огня/дыма: 12 139 911 байт, вход 1×3×320×320, выход 1×6×2100. Порядок классов fire/smoke проверен по ONNX metadata. Она не является моделью ДТП; точность на Iowa не измерена.
- Промежуточные результаты остаются в коллекторе. За сутки без кандидатов — 96 публикаций вместо 17 280. Лимит 400 попыток/сутки, максимум 5 клипов/сутки, подтверждение на двух разных кадрах с разницей до 6 секунд, cooldown и сохраняемые локальные счётчики.
- Начальный кадр с подозрением не заменяется пустым heartbeat: иначе его последующая дедупликация на сервере могла бы потерять подтверждение события.
- Видео хранится в кольце; H.264-фрагменты ремультиплексируются в MP4 без повторного кодирования и искусственного увеличения разрешения.
- Некорректный ledger, исчерпанная квота, отсутствующая авторизация и ошибка предзапусковой проверки останавливают процесс.

## Реальный облачный тест

GitHub Actions: https://github.com/subrosa5/roadwatch/actions/runs/43472594823

Проверенный commit: `9a81d467b5c6d9716e5f9fd3dcf472a45c62ef09`. Результат success. Linux x86_64, контейнер ограничен `--cpus=0.5 --memory=512m --memory-swap=512m`, без записи в root filesystem, без приватных API credentials.

Получен один свежий JPEG из публичного HLS Iowa DOT через FFmpeg, выполнены шесть inference. Медиана CPU после прогрева: **46.32 мс/кадр**. Консервативная сумма process high-water RSS: **228.29 МиБ**. Это короткий тест совместимости в облаке, не долговременный нагрузочный тест и не измерение фактического узла Botkeep. Авторизация backend и создание реального события в этой проверке не выполнялись.

Модель и SHA-256: `collector/botkeep/model.lock.json`. В карточке весов MIT, в metadata и базовой модели AGPL-3.0; обе ссылки и исходные уведомления сохранены в THIRD_PARTY_NOTICES. Бинарные веса не включены в ZIP.

Дополнительно пройдены 6 тестов публикации, 4 проверки механики коллектора, прямой запуск default preflight с камерой и запуск распакованного ZIP на локальном видео. Локальный тест служит проверкой сборки, компьютер владельца не используется для производственного мониторинга.

## Артефакт и запуск

Сборка: `python3 tools/build-botkeep.py /absolute/path/roadwatch-botkeep.zip`.

Исходники и пошаговая инструкция: [collector/botkeep/README.md](../collector/botkeep/README.md).

Первый запуск на Botkeep — `ROADWATCH_MODE=preflight`. Серверный флаг камеры уже подготовлен. После успешной проверки на самом хосте нужны два runtime-секрета и `ROADWATCH_MODE=run`. Полная актуальная инструкция: [OWNER_FINAL_STEPS.md](OWNER_FINAL_STEPS.md).

Дополнения от 14 ноября: отдельные heartbeat активности, запрос JPEG/рамок по viewer lease, push-очередь, автоматическая очистка при активности API/коллектора и устойчивый outbox клипов реализованы. [Подробности и пределы проверки](RUNTIME_COMPLETION.md). Постоянный экземпляр Botkeep и доставка на устройстве владельца ещё не проверены.

Последний probe и полный Linux E2E: [отчёт публикации](RUNTIME_COMPLETION.md#подтверждение-публикации-14112026).
