# Облачное сопровождение транспорта

Рамка относится к настоящему транспортному объекту, имеет ID и приходит вместе с тем изображением, на котором рассчитана. Браузер не выполняет inference. Это дополнение к огонь/дым pipeline, а не замена распознавания происшествий зелёной разметкой.

## Путь данных

Iowa HLS → FFmpeg с pacing и кольцом записи → кадры 5 fps → NanoDet COCO (car, motorcycle, bus, truck) каждые 0.5 секунды → forward/backward-checked Lucas–Kanade optical flow между детекциями → short-term ID → приватный `/tracking` → JPEG + рамки + ID во фронте.

Детектор закреплён по upstream commit и SHA-256: [OpenCV Zoo NanoDet](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7/models/object_detection_nanodet). ONNX 3800954 байта, Apache-2.0; адаптер и лицензия находятся в `collector/vendor`. Персональные идентификаторы и номера не распознаются.

После запуска облачного коллектора выбрать CBTV51 → «Транспорт · трекинг». «Живое видео» — оригинальный HLS без наложения несовпадающих по времени рамок. «Огонь / дым» — отдельные результаты incident-модели раз в пять секунд. Запись клипов, подтверждение кандидатов, review и push продолжают работать независимо от транспорта.

## Согласованность и потери

`/api/cameras/:id/tracking` принимает только service-role, одобренную камеру, vehicle labels, ограниченные ID и JPEG с проверяемым SHA-256 = frame_id. Изображение и все рамки сохраняются одним R2-объектом. Canvas проецируется в реальную область изображения, включая letterboxing. На неактивной вкладке обработка в облаке продолжается, но публикация кадров просмотра прекращается после истечения viewer lease.

После потери надёжных optical-flow точек рамка удаляется. Единичный пропуск детектора не сбрасывает ID, если движение ещё измеряется; такая поддержка ограничена 1.5 секунды от последней детекции. Большой разрыв, смена разрешения и рестарт очищают треки. После перекрытия или потери машины её ID может измениться: это краткосрочный track, не постоянная идентификация. Просроченные более трёх секунд изображения не выдаются за актуальное сопровождение.

## Бесплатный бюджет

Цель — 5 обработанных кадров/с, не 25–30 fps. Фактический просмотр зависит от HTTP latency и ресурса хоста; непрерывный HLS уже имеет задержку источника. Private API пересылает последний кадр, не гарантирует доставку каждого промежуточного кадра.

Для ограничения R2/API есть отдельная квота просмотра 24000 публикаций/сутки: около 80 минут при полных 5 fps. Она **не отключает** фоновый трекер, fire/smoke и запись событий. После исчерпания frontend перестаёт показывать свежие рамки, не подменяет их старыми. В течение месяца при максимуме это до 744000 tracking writes, плюс preview и служебные операции; несколько одновременно открытых вкладок увеличивают число чтений. Утверждать неограниченный круглосуточный просмотр при бесплатном ресурсе нельзя.

## Проверки

- Тесты трекера: сохранение ID при измеренном смещении и новой детекции, удаление потерянного объекта, reset после разрыва, проверка хеша модели.
- Worker: роли, viewer lease, атомарная пара JPEG/ID, отказ при несовпадении SHA, отдельная квота; машины не создают инциденты.
- Сквозной тест: настоящий collector/optical-flow/FFmpeg → Worker → чтение согласованных frame_id/track_id; incident MP4 и Range остаются исправны. Детекторы в транспортном тесте явно синтетические, production не затронут.
- Реальный записанный ночной Iowa sample 13.11.2026: 22 обработанных кадра, 15 с треками, два ID; 2 detector observations + 13 optical-flow observations. Веса настоящие, разметка не задана вручную. Это короткий smoke test, не измерение полноты/точности. Видео `web/clips/vehicle-proof.mp4` явно помечено RECORDED / NOT LIVE.
- Browser QA проверяет получение новых tracking frame_id, видимость ID и переключение режимов; браузерный detector не загружается.

Для фактического live требуется запуск на аккаунте облачного хоста: [единая инструкция](OWNER_FINAL_STEPS.md). Пока такого экземпляра нет, наличие опубликованного интерфейса не означает работающий мониторинг. Распознавание ДТП остаётся отдельной невалидированной исследовательской задачей.

Первый cloud load test: 4.91 fps, 101 кадр за 20.58 секунды, 46 track observations. Консервативная сумма high-water RSS 356.89 МиБ превысила предварительный порог 350 МиБ; проверка корректно завершилась failure. Следующая версия сохраняет исходное разрешение камеры вместо upscale до 640, измеряет cgroup memory.peak и требует <384 МиБ по сумме RSS и <448 МиБ по общей памяти контейнера при лимите 512 МиБ. Это сохраняет измеримый запас и учитывает память FFmpeg/кеша/служебных процессов.
