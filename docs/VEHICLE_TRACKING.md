# Облачное сопровождение транспорта

Рамка относится к настоящему транспортному объекту, имеет ID и приходит вместе с тем изображением, на котором рассчитана. Браузер не выполняет inference. Это дополнение к огонь/дым pipeline, а не замена распознавания происшествий зелёной разметкой.

## Путь данных

Iowa HLS → FFmpeg с pacing и кольцом записи → кадры 4 fps на Hostrix (5 fps в общем профиле) → NanoDet COCO (car, motorcycle, bus, truck) с измеряемым интервалом 0.5–1 секунды → forward/backward-checked Lucas–Kanade optical flow между детекциями → short-term ID → приватный `/tracking` → JPEG + рамки + ID во фронте.

Детектор закреплён по upstream commit и SHA-256: [OpenCV Zoo NanoDet](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7/models/object_detection_nanodet). ONNX 3800954 байта, Apache-2.0; адаптер и лицензия находятся в `collector/vendor`. Персональные идентификаторы и номера не распознаются.

После запуска облачного коллектора выбрать CBTV51 → «Транспорт · трекинг». «Живое видео» — оригинальный HLS без наложения несовпадающих по времени рамок. «Огонь / дым» — отдельные результаты incident-модели раз в пять секунд. Запись клипов, подтверждение кандидатов, review и push продолжают работать независимо от транспорта.

## Согласованность и потери

`/api/cameras/:id/tracking` принимает только service-role, одобренную камеру, vehicle labels, ограниченные ID и JPEG с проверяемым SHA-256 = frame_id. Изображение и все рамки сохраняются одним R2-объектом. Canvas проецируется в реальную область изображения, включая letterboxing. На неактивной вкладке обработка в облаке продолжается, но публикация кадров просмотра прекращается после истечения viewer lease.

После потери надёжных optical-flow точек рамка удаляется. Единичный пропуск детектора не сбрасывает ID, если движение ещё измеряется; такая поддержка ограничена 1.5 секунды от последней детекции. Большой разрыв, смена разрешения и рестарт очищают треки. После перекрытия или потери машины её ID может измениться: это краткосрочный track, не постоянная идентификация. API и фронт используют единый порог свежести последнего кадра: 5 секунд. При большей задержке последнее согласованное изображение остаётся видимым, статус явно меняется на ожидание новых кадров, рамки сереют. Возраст показанного кадра виден в плеере.

## Бесплатный бюджет

Цель Hostrix — 4 обработанных кадра/с; общий профиль допускает 5 fps. Фактический просмотр зависит от HTTP latency и ресурса хоста; непрерывный HLS уже имеет задержку источника. Коллектор отправляет до 8 реальных JPEG/annotation пар одним запросом, с fallback на одиночный кадр для старого API. Браузер держит не более 24 кадров и воспроизводит их по captured_at; координаты не экстраполируются. Переполнение и позднее получение могут пропускать промежуточные кадры. Вкладки получают независимые leases, поэтому закрытие одной не отменяет другую.

Для ограничения R2/API есть отдельная квота просмотра 24000 кадров/сутки: около 100 минут при полных 4 fps (80 минут при 5 fps). Квота учитывает каждый кадр пакета. Она **не отключает** фоновый трекер, fire/smoke и запись событий. После исчерпания frontend перестаёт показывать свежие рамки, не подменяет их старыми. В течение месяца при максимуме это до 744000 кадров tracking, а число writes уменьшается пакетами, плюс preview и служебные операции; несколько одновременно открытых вкладок увеличивают число чтений. Утверждать неограниченный круглосуточный просмотр при бесплатном ресурсе нельзя.

## Проверки

- Тесты трекера: сохранение ID при измеренном смещении и новой детекции, удаление потерянного объекта, reset после разрыва, проверка хеша модели.
- Worker: роли, viewer lease, атомарная пара JPEG/ID, отказ при несовпадении SHA, отдельная квота; машины не создают инциденты.
- Сквозной тест: настоящий collector/optical-flow/FFmpeg → Worker → чтение согласованных frame_id/track_id; incident MP4 и Range остаются исправны. Детекторы в транспортном тесте явно синтетические, production не затронут.
- Реальный записанный ночной Iowa sample 13.11.2026: 22 обработанных кадра, 15 с треками, два ID; 2 detector observations + 13 optical-flow observations. Веса настоящие, разметка не задана вручную. Это короткий smoke test, не измерение полноты/точности. Видео `web/clips/vehicle-proof.mp4` явно помечено RECORDED / NOT LIVE.
- Browser QA проверяет получение новых tracking frame_id, видимость ID и переключение режимов; браузерный detector не загружается.

Для фактического live требуется запуск на аккаунте облачного хоста: [единая инструкция](OWNER_FINAL_STEPS.md). Экземпляр Hostrix уже подтверждён реальным heartbeat и ingestion; полный суточный прогон ещё не завершён. Распознавание ДТП остаётся отдельной невалидированной исследовательской задачей.

Первый cloud load test: 4.91 fps, 101 кадр за 20.58 секунды, 46 track observations. Консервативная сумма high-water RSS 356.89 МиБ превысила предварительный порог 350 МиБ; проверка корректно завершилась failure. Следующая версия сохраняет исходное разрешение камеры вместо upscale до 640, измеряет cgroup memory.peak и требует <384 МиБ по сумме RSS и <448 МиБ по общей памяти контейнера при лимите 512 МиБ. Это сохраняет измеримый запас и учитывает память FFmpeg/кеша/служебных процессов.

## Итоговая облачная проверка

[Повторный Linux load test](https://github.com/subrosa5/roadwatch/actions/runs/43588101584), commit `902b911`: success. Docker ограничен 0.5 CPU / 512 МиБ, реальный Iowa HLS, настоящие NanoDet + optical-flow + fire/smoke. 101 кадр за 20.58 секунды, **4.907 fps**, 11 track observations; inference CPU 2.63 секунды, консервативная сумма high-water RSS **354.45 МиБ**. Контейнерный cgroup counter также прочитан; для оценки запаса используется консервативная сумма RSS. Двадцать секунд не являются проверкой суток работы или accuracy, приватный API в load test не вызывался.

[CI полного контура](https://github.com/subrosa5/roadwatch/actions/runs/43587718355): success, 37 Node + 16 Python tests, синтетический transport E2E проверил tracking ID/JPEG/hash и запись incident MP4/Range. После CI изменены только отсутствие upscale и измерение памяти; тест FFmpeg/клипов повторён локально (4 passed), затем новый load test прошёл в облаке.

## Реальный Hostrix и транспорт кадров, 14 ноября

На аккаунте владельца mode=run: heartbeat state=running, реальные fire/smoke observations и JPEG доходят в приватный API. Throughput 4.079 fps, возраст файла до 0.183 с, RSS upper sum 302.42 МиБ. При открытом tracking GET получены реальные vehicle ID и optical_flow рамки. Однако сетевой возраст публикуемого кадра 2.8–4.2 секунды конфликтовал со старым frontend cutoff 3 секунды — отсюда пустой экран. Порог согласован с server acceptance 5 секунд, опрос восстанавливается без пятисекундной паузы.

Новый Hostrix ZIP задаёт 4 fps вместо нестабильно достижимых 5; model/throughput gates сохранены. Суточный inference budget 36000 CPU-секунд покрывает оценку 0.35 CPU-сек/сек (30240 за сутки) с запасом. Декодирование FFmpeg не входит в этот счётчик, его нагрузка дополнительно ограничена ресурсом хоста. Бюджет не доказывает безотказную работу 24 часа и не отменяет лимиты платформ.
