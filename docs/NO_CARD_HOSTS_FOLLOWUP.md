# Постоянный CV без карты: новые кандидаты

Повторное исследование: 13 ноября 2026. Это дополняет IOWA_RESOURCE_PLAN.md. Утверждение «постоянного бесплатного исполнителя не найдено» относится к прежней выборке, а не к доказательству невозможности: найдены дополнительные провайдеры с подходящими опубликованными условиями.

Ни в одном новом сервисе аккаунт или контейнер в ходе исследования не создан. Рекламные условия, документация и реально выполненный запуск — разные уровни подтверждения.

## Каким должен быть первый эксперимент

Сначала один компактный коллектор, одна камера CBTV51 (480×270), анализ одного кадра каждые 5 секунд. Это целевые параметры эксперимента, не измеренная производительность этих хостингов. Фронт с двумя потоками остаётся в Sites; первая фоновая проверка не требует переносить фронт и базу.

Из ранее полученного AVERAGE-BANDWIDTH=133995 бит/с:

- Видео одной камеры: примерно 1.447 ГБ/сутки, 44.862 ГБ за 31 день без overhead.
- Минутный буфер сжатого видео: примерно 1.005 МБ, не включая FFmpeg, Python и модель.
- 17280 inference/сутки при 0.2 FPS; это не 17280 записей в D1.
- Если inference занимает 1 CPU-секунду на кадр, средняя потребность самой модели 0.2 vCPU; ещё нужны декодирование и сеть. При 0.5 vCPU запас нельзя считать доказанным до измерения.

Проверка готовности: реальное подключение к HLS → реально декодированный кадр → проверенная модель и SHA-256 → измерение RSS/CPU → минутный буфер → воспроизводимый MP4 → создание и чтение события из приватного API. Наличие модели огня/дыма не доказывает способность распознавать ДТП.

API-ограничение 500 наблюдений/сутки сохраняется. Перед постоянным запуском нужно изменить collector: хранить промежуточные результаты локально, отправлять heartbeat раз в 15 минут и два свежих подтверждающих кадра кандидата. Один heartbeat на одну камеру даёт 96 записей/сутки; остальные записи резервируются под события. Это проект изменения, не уже реализованный режим.

На Hostless проверять один worker с максимумом 0.5 vCPU, 1024 MB и одной репликой, без второй базы и лишнего web-процесса. На Botkeep начинать с одного процесса в существующем Python runtime; память 512 MiB может потребовать более компактной модели. Вторую камеру добавлять только после измерений.

## Резерв без нового постоянного сервера

GitHub Actions способен выполнять редкие автономные окна анализа. По текущим официальным расценкам GitHub Free включает $12 eligible compute/месяц, ubuntu-slim стоит $0.002 за округлённую вверх минуту. Пример: каждые 30 минут, не более трёх учитываемых минут на запуск — 1488 запусков × 3 × $0.002 = $8.928 из включённого бюджета за 31 день. Остальные workflows используют тот же общий бюджет. Условия и длительность нужно проверить в реальном аккаунте, включать платное превышение нельзя.

Если каждое окно содержит 30 секунд видео, временное покрытие одной камеры составит 30/1800 = 1.67%. Это может обнаружить длительное задымление или последствия инцидента, но не заменяет постоянное наблюдение за ДТП. Расписание GitHub может задерживаться или пропускаться; интервалы не гарантированы. Такой вариант не включается молча вместо поставленной задачи 24/7.

## Границы проверки

Страницы прочитаны через веб-поиск по официальным сайтам. Прямые HTTP-запросы из исполнительной среды к Hostless/Belmo/странице Terms Botkeep вернули 403; это не доказательство отсутствия сервиса или невозможности пользовательского входа. Прямой запрос к публичному status API Botkeep прошёл. Регистрация, выделение бесплатного слота и прохождение наших тестов пока не подтверждены. Готовых подключений Hostless/Botkeep/Northflank в проверенном каталоге интеграций не найдено; документация Hostless описывает собственные CLI/API/MCP для последующего штатного доступа.
