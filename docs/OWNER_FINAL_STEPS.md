# Hostrix: включить постоянный мониторинг

Обновлено 14 ноября 2026 после фактической проверки на аккаунте владельца. Сервер Hostrix создан, зависимости и модели установлены. Оба preflight gate прошли: 85 кадров за 20.13 секунды, 4.22 fps, 90 track observations, stale_frames=0. Занято около 397 МБ диска; RSS upper sum 324.30 МиБ, cgroup memory peak 237.13 МиБ. Это короткий тест, не многосуточная проверка.

Сообщение Hostrix «main.py finished without an error» и exit code 0 ожидаемы в ROADWATCH_MODE=preflight. Это не запуск production.

1. Открыть Startup → Environment variables → Paste a whole .env file.
2. Вставить подготовленный блок настроек из системного буфера и сохранить. Он содержит INGEST_TOKEN, SITES_SERVICE_TOKEN и ROADWATCH_MODE=run. Значения не публиковать в сообщениях/скриншотах и не добавлять в GitHub.
3. Убедиться, что ROADWATCH_MODE заменён с preflight на run. Команда остаётся python3 -u hostrix_bootstrap.py --repair, автоматическая установка пакетов Hostrix выключена, Python 3.12.
4. Start. Сначала повторяются короткие проверки, затем процесс должен продолжить работу. Появятся публикации camera/frame_id, а на приватном фронте — свежий heartbeat коллектора.
5. Открыть CBTV51 → «Транспорт · трекинг». Проверить свежий timestamp, совпадение ID/рамок и изображения. Оригинальный HLS доступен отдельным режимом.
6. После успешного старта включить Restart automatically if it crashes. Закрыть фронт на несколько минут, затем проверить, что heartbeat остаётся свежим. Просмотр кадров публикуется только при активном viewer lease, фоновый inference и события работают независимо.
7. По желанию разрешить push кнопкой во фронте. Реальную доставку на устройстве проверить отдельно.

В состоянии запуска не создавать вымышленные реальные происшествия для проверки. Пустой журнал нормален. Детектор огонь/дым требует оценки качества на этих камерах; исследовательский ДТП-классификатор не подключён к production.

Текущий профиль Hostrix: до 4 fps с подбором 2–4 fps по измеренной нагрузке; предыдущие измерения при цели 5 fps колебались 3.68–4.22. Квота передачи tracking-кадров — 24000/сутки, около 100 минут при полных 4 fps; она не отключает фоновый анализ. Статус 24/7 требует проверки длительной работы и не гарантируется бесплатным хостом.

История восстановления установки: [HOSTRIX_RECOVERY.md](HOSTRIX_RECOVERY.md). Протокол трекинга: [VEHICLE_TRACKING.md](VEHICLE_TRACKING.md).


Обновление уже работающего сервера: Stop → Files → Upload files → roadwatch-hostrix-fix.zip с рабочего стола → Unzip с заменой → Start. Redeploy не использовать: он удаляет установленные пакеты. Secrets и команда bootstrap остаются прежними. На сайте после обновления нажать Cmd+Shift+R и выбрать CBTV51 → «Транспорт · трекинг».


При sustained_resource_budget_exceeded использовать актуальный ZIP с profile_version=3. Он выполняет общий optical flow для всех объектов и выбирает частоту по фактическим измерениям. В логах должны появиться configuration_loaded (profile_version=3), selected_fps и throughput_gate_passed=true. Во время проверки автоматический restart выключен. Измерение реального потока может пройти до трёх попыток с более низкой частотой; при превышении памяти или отсутствии потока дальнейших попыток нет.
